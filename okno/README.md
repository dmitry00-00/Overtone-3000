# «Окно» — цифровая версия

Фаза 0 — автомат раунда и партии, схема Postgres, импорт колод (разделы 1–8).
Фаза 1 — FastAPI, бот @Overtone_3000_bot, Mini App (раздел 9). ИИ не подключён:
обстоятельства из колоды, журналист — человек, при его отсутствии заглушка.

```
.venv/bin/pytest -q -p no:warnings           # 52 теста; 7 из них через Postgres (okno_test)
.venv/bin/python scripts/run_scenarios.py    # три сценария с протоколом
.venv/bin/python scripts/init_db.py          # миграции + импорт колод (OKNO_DSN, по умолчанию postgresql://localhost/okno)
```

## 1. Модель фаз

```
OPENING ──► PREP ──► STATEMENT ──► REVEAL ──► RESPONSE ──► VERDICT ──► LEDGER ──► SUMMARY ──► CLOSED
 мгнов.     10ч        4ч         мгнов.        4ч           4ч          2ч          2ч
```

Окна — доли `Config.phase_shares` от `Config.round_duration` (по умолчанию 26 ч).

**Правило завершения фазы:** все, от кого ждут действия, действовали **или** истёк
дедлайн — что раньше. Кого ждут, отвечает `Round.pending(ctx)`:

| Фаза | Ждём |
|---|---|
| PREP | готовность обеих команд (`mark_ready`) |
| STATEMENT | выступление от каждой активной команды |
| RESPONSE | от каждой команды реплику **или** вызов |
| VERDICT | карточку судьи: вердикт + пять отметок каждой команде + решения по вызовам — одно атомарное действие |
| LEDGER | опору от каждой выступавшей команды; выбор хода от победителя, если ходов больше одного |
| SUMMARY | сводку журналиста |

**Время перехода** — момент действия; при таймауте — дедлайн, а не момент, когда
сервер это заметил; для мгновенных фаз — момент предыдущего перехода. Поэтому один
`tick` через месяц проводит партию через все окна с правильными временными метками
(сценарий 3).

## 2. Таймауты (раздел 4 промпта → код)

| Пропуск | Маршрут | Эффект |
|---|---|---|
| PREP без готовности | → STATEMENT | — |
| Одна команда не сдала выступление | STATEMENT → REVEAL → **LEDGER** (RESPONSE и VERDICT пропущены) | `Verdict(by_forfeit=True)`, отметок нет ни у кого; победитель выбирает ход, опору пишет только он |
| Обе не сдали | STATEMENT → **CLOSED** | апория `NO_STATEMENTS`, системная сводка, серии обнуляются |
| Реплика не сдана | → VERDICT | без последствий (таблица промпта их не задаёт) |
| Судья не вынес вердикт | VERDICT → LEDGER | апория `NO_VERDICT`, отметок нет, нерассмотренные вызовы без эффекта; опоры пишутся |
| Судья выбыл / его нет | RESPONSE → LEDGER | то же, без ожидания |
| Команда не записала опору | LEDGER → SUMMARY | заявление «команда не сформулировала опору», `weak=True`, нумеруется, уязвимо для вызова |
| Победитель не выбрал ход | LEDGER → SUMMARY | ход по умолчанию: шаг себе, иначе откат, иначе ничего |
| Журналист не опубликовал / его нет | SUMMARY → CLOSED | публикует `summary_fallback` (в Фазе 0 — заглушка, `author="ai"`) |
| Игрок выбыл | — | команда продолжает; при нуле активных — текущий раунд закрывается апорией `TECHNICAL`, новые раунды не открываются, партия уходит в разбор |
| Разбор не завершён за `debrief_window` (7 дней) | DEBRIEF → UNCOUNTED | партия закрыта и **не засчитана**, экспорт закрыт |

## 3. Трек и реестр

- `0 → 1` — на второй победе подряд. Первая пишется в события как `STREAK_PROGRESS`
  без сдвига (материал для проигрыша трека в разборе). Серия прерывается любым
  не выигранным обменом, включая апорию.
- Победитель выбирает `advance` / `push_back` в фазе LEDGER. Границы 0 и 5 жёсткие:
  недоступные ходы не предлагаются, при единственном ходе выбор не запрашивается.
- Вызов заявляется вместо реплики, минимум два разных существующих неотозванных
  заявления соперника. Исход обмена при вызове определяет **только** решение по вызову;
  «кто убедил» судья при этом не применяет:
  - засчитан → соперник −1, вызывающий +1 (по правилам трека, включая серию из 0),
    заявления помечаются `challenged_in_round`;
  - отклонён → соперник +1 бесплатно.
  - оба вызвали → каждый решается независимо, эффекты складываются.
- Отзыв заявления — в любой фазе своей команды: −1 на треке, пометка в реестре,
  запись `StructuralEvent(atom="revise_under_evidence")` — **мимо** карточки судьи.
  Номер не переиспользуется.
- Судья отклоняет уклончивую опору (`reject_claim`) — команда пишет заново
  в том же окне.

## 4. Два счёта разведены (инвариант)

`Track` (позиции, события) и `Round.marks` + `Game.structural` — разные объекты,
ни одна функция их не складывает. `Game.outcome` считается только по треку.
`Game.export_allowed` истинно только при `COMPLETED` с заполненным
`debrief_completed_at`.

## 5. Апория — первый класс

`Verdict.is_aporia` + `AporiaReason` (`NO_STATEMENTS`, `NO_VERDICT`,
`JUDGE_RULED_NOBODY`, `TECHNICAL`, `TIE`). Раунд с апорией проходит те же фазы
LEDGER/SUMMARY, что и обычный; партия с апорией во всех раундах уходит в разбор
и закрывается штатно (тест `test_whole_game_by_timeouts_closes_correctly` —
блокирующий критерий приёмки).

## 6. Схема БД

Таблицы раздела 3 промпта плюс то, чего требует автомат. Отличия помечены в SQL:

- **+** `round_transitions` — журнал переходов с временем и признаком таймаута;
  `track_events` — проигрыш трека; `structural_events` — плюсы мимо карточки судьи;
  `round_claim_drafts` — опора внутри окна LEDGER до попадания в реестр;
  колонки `ready_teams`, `forfeit_teams`, `move_choice` в `rounds`, `streak` в
  `game_projects`, `weak`/`retracted_in_round`/`challenged_in_round` в `ledger_claims`,
  `draft_value` в `marks`, `outcome_json`/`technical_aporia_from` в `games`.
- **~** `challenges.claim_ids` → `claim_numbers` (адресация номером в реестре);
  `debriefs.track_replay_json` не хранится — выводится из `track_events` + `statements`.
- `rounds.circumstance_code` без FK: в Фазе 2 обстоятельства генерирует модель.
- На `statements`, `ledger_claims`, `*_events` нет ни одного delete. Правка выступления
  внутри окна перезаписывает текст (`edit_count` растёт); если нужна история версий —
  отдельная таблица, пока не делал.
- Единица работы — партия: `load(id, for_update=True)` → действие → `save`.
  Партия — десятки строк, полный upsert дёшев; блокировка строки `games` снимает гонки.

## 7. Решения, принятые по умолчанию (утверждены 20.09, корректируем по ходу игры)

ТЗ механики в папке нет, поэтому там, где промпт неоднозначен, принято решение.
Каждое меняется в одном месте.

1. **Где победитель выбирает ход.** Промпт кладёт `move` в `verdicts`, но говорит
   «победитель выбирает». Реализовано: выбор в фазе LEDGER, победитель и так там
   действует; на таймаут — ход по умолчанию. Альтернатива: судья спрашивает и вносит
   в карточку (тогда карточка дольше минуты).
2. **«Проверка реестром» при 3 → 4 → 5** трактована как обычный вызов в том же раунде
   (вызов в RESPONSE против только что раскрытого выступления). Если в ТЗ это
   отложенная проверка в следующем раунде — менять `_resolve_exchange`.
3. **Серия для 0 → 1 считается по выигранным обменам**, а не по выбранным шагам:
   победа с `push_back` тоже входит в серию. Апория серию рвёт.
4. **Шаг по засчитанному вызову подчиняется правилам трека** (из 0 — серия). Можно
   сделать безусловным.
5. **Исход партии — по сдвигу от старта** (`scoring="delta"`), ничья → апория `TIE`.
   Есть `"absolute"`. Стартовые позиции 0–3 из колоды делают абсолютный счёт
   несправедливым, но «провёл проект дальше» можно читать и так.
6. **Досрочное завершение при достижении 5** (`end_on_norm=True`). Критерий
   «партии доходят до пятого раунда» намекает, что вырождение раньше — болезнь,
   но правило нужно подтвердить.
7. **Дедлайны фаз относительно фактического начала фазы**, не по фиксированному
   расписанию. Быстрые команды ускоряют партию. Макет пишет «окно раунда закроется
   в 21:00» — если нужно расписание, это замена `phase_deadline` на сетку.
8. **Ноль активных игроков в команде** → партия сразу в разбор, а не формальные
   апорийные раунды до конца недели.
9. **Одна команда не сдала выступление** → выступившая всё же пишет опору
   (обмен состоялся, слова сказаны), проигравшая — нет.
10. **Реплика не сдана** — без последствий; таблица таймаутов её не упоминает.
11. **Оба вызова в одном раунде** — независимое сложение эффектов.
12. **Отзыв заявления, находящегося под текущим вызовом** — разрешён; если вызов
    затем засчитают, команда получит и −1 за отзыв, и −1 за вызов. Возможно, отзыв
    должен снимать вызов с этого заявления.
13. **Команда выбыла после вердикта** (найдено круговым тестом через БД): вердикт
    остаётся, реестр закрывается штатно (ход по умолчанию, опоры), затем партия
    уходит в разбор. Апория `TECHNICAL` ставится только раунду без вердикта.

## 9. Фаза 1: запуск на маке

### Переменные (`okno/.env`, в `.gitignore`)

```
OKNO_BOT_TOKEN=...                       # от @BotFather; без него бот не стартует, API работает
OKNO_WEBAPP_URL=https://<туннель>        # https-адрес Mini App; нужен для кнопки «Открыть «Окно»»
OKNO_APP_SHORT_NAME=okno                 # необязательно: short name из /newapp — тогда бот шлёт прямые ссылки t.me/Overtone_3000_bot/okno?startapp=<id>
OKNO_DSN=postgresql://localhost/okno     # по умолчанию так
OKNO_DEV_AUTH=1                          # только для разработки: авторизация заголовком X-Dev-User вместо подписи Telegram
OKNO_TICK_INTERVAL=30                    # секунд между проверками дедлайнов
```

### Порядок

1. `psql -d postgres -c "create database okno"` (один раз), затем `scripts/init_db.py`.
2. `cd webapp && npm install && npm run build` — `dist/` раздаётся с корня API.
3. Туннель до `127.0.0.1:8010`: `cloudflared tunnel --url http://127.0.0.1:8010` (адрес меняется при каждом запуске — удобнее именованный туннель). Адрес → `OKNO_WEBAPP_URL`.
4. В @BotFather: `/setmenubutton` → тот же адрес (кнопка меню в личке). Необязательно: `/newapp` → short name в `OKNO_APP_SHORT_NAME`.
5. `.venv/bin/python -m okno.api.app`.
6. Бота — в групповой чат, там `/new`. Остальные входят по ссылке из ответа бота и выбирают роль. Старт — из приложения, когда есть обе команды и судья.

### Как устроено

- **Единица работы** (`service.mutate`): `load(for_update)` → действие → `save` → если сменилась фаза/статус, запись в `outbox`. Бот раз в 5 с забирает outbox и шлёт в чат партии (или в личку каждому, если чат не привязан). Тексты — `bot/texts.py`, тон протокола.
- **Планировщик** — asyncio-задача в том же процессе: раз в `OKNO_TICK_INTERVAL` секунд находит партии с истёкшим дедлайном и вызывает `Game.tick`. В dev-режиме есть `POST /api/tick`.
- **Видимость** (`api/views.py`): выступление соперника — только после REVEAL; реплики и вызовы — после RESPONSE (судья видит вызовы сразу, они нужны для карточки); черновик опоры соперника — никогда; отметки соперника — только в разборе; карта публики — судье и журналисту, всем — после закрытия раунда.
- **`prompt`** — первое поле ответа `GET /api/games/{id}`: «что от меня ждут прямо сейчас» + дедлайн. Главный экран строится от него.
- **Карточка судьи** измеряет `fill_seconds` от открытия экрана до отправки — критерий приёмки «медиана ≤ 60» считается по `verdicts.fill_seconds`.
- **Реестр**: пометки «подозрительно» и выбранная пара живут в браузере игрока (`localStorage`), на сервер не уходят.
- Dev-режим без Telegram: `http://127.0.0.1:8010/?dev=a1:Аня` (и `OKNO_DEV_AUTH=1` у сервера); второй игрок — другой `dev=`.
- **Среда Mini App**: шапка и фон Telegram красятся в цвет листа (`setHeaderColor`/`setBackgroundColor`, обе темы); вертикальные свайпы отключены, чтобы скролл не закрывал приложение; пока на экране несохранённый черновик (выступление, реплика, опора, вызов, сводка, отметка разбора), Telegram спрашивает подтверждение перед закрытием. Бот при старте сам ставит кнопку меню на `OKNO_WEBAPP_URL` и регистрирует команды — `/setmenubutton` в BotFather не нужен.
- **Колода проектов расширена до 40** (П-25…П-40, по десять на каждый старт 0–3). Новые карты — черновик модели: по анти-требованию ТЗ их нужно проверить вручную (пометка в конце `okno-decks.md`).

- История версий выступления при правке в окне — хранится только последняя (см. раздел 6).
