# «Окно» — развёртывание на хостинге

Один процесс: API + планировщик дедлайнов + бот @Overtone_3000_bot + Mini App
(статика). Рядом нужен PostgreSQL. Миграции и импорт колод выполняются сами
при старте — отдельных шагов инициализации нет.

## Вариант 0: BotHost (bothost.ru) — основной

Для BotHost в корне репозитория лежит свой `Dockerfile`: он сам собирает Mini App,
ставит зависимости и **поднимает Postgres внутри контейнера** с данными
в `/app/data` (постоянное хранилище платформы). Внешняя база не нужна.

1. Бот подключён к репозиторию `dmitry00-00/Overtone-3000`.
2. «Запуск» / доп. настройки: включить **«Использовать собственный Dockerfile»**.
3. «Домен»: включить домен (поле «свой домен» оставить пустым — будет
   `bot-…bothost.tech`). Внутренний порт — **8080** (приложение читает `PORT`).
4. «Переменные»:
   - `OKNO_WEBAPP_URL=https://bot-1790614127-7064-dmitriy-00.bothost.tech`
   - токен: вкладка «Токен» (переменная `BOT_TOKEN`) или `OKNO_BOT_TOKEN` — понимаются обе.
5. Передеплоить. В логах должно быть `бот @Overtone_3000_bot` и `Uvicorn running on http://0.0.0.0:8080`.

Проверка: `https://bot-…bothost.tech/api/health` → `{"ok":true}`; в Telegram у бота
появляется кнопка «Окно».

Если позже понадобится внешняя база — задать `DATABASE_URL`: встроенный Postgres
тогда не запускается.

## Вариант А: хостинг с Docker (Amvera, Timeweb Cloud Apps, Railway и подобные)

1. Залейте содержимое архива в проект хостинга (Dockerfile в корне — платформа
   соберёт сама).
2. Создайте на платформе PostgreSQL и передайте приложению строку подключения:
   переменная `OKNO_DSN` или стандартная `DATABASE_URL` — понимаются обе,
   `postgres://` нормализуется.
3. Переменные окружения — по `.env.example`. Обязательные:
   - `OKNO_BOT_TOKEN` — токен бота;
   - `OKNO_WEBAPP_URL` — https-адрес, который платформа выдала приложению
     (Mini App обязан жить на HTTPS).
4. Порт: приложение слушает `OKNO_PORT` (8010) или `PORT`, если платформа
   задаёт свой. Health-check: `GET /api/health`.

## Вариант Б: VPS с docker-compose

```
cp .env.example .env   # заполнить OKNO_BOT_TOKEN и OKNO_WEBAPP_URL
docker compose up -d --build
```

HTTPS поверх :8010 — вашим обычным способом (nginx/caddy + сертификат).

## Вариант В: хостинг с голым Python (без Docker)

Python ≥ 3.12, PostgreSQL рядом:

```
pip install -r requirements.txt
export PYTHONPATH=src OKNO_HOST=0.0.0.0 OKNO_BOT_TOKEN=... OKNO_WEBAPP_URL=... OKNO_DSN=...
python -m okno.api.app
```

## После первого запуска

- Бот сам ставит кнопку меню на `OKNO_WEBAPP_URL` и регистрирует команды —
  в BotFather ходить не нужно. Проверка: в личке бота `/start`, кнопка
  «Открыть «Окно»» открывает приложение.
- Партия создаётся в групповом чате командой `/new`.

## Важно

- **Одна реплика.** Бот работает через polling: две копии процесса с одним
  токеном конфликтуют (Telegram отдаёт updates только одной). Локальную копию
  на маке перед запуском хостинга остановить — или запускать её
  с `OKNO_RUN_BOT=0`.
- `OKNO_DEV_AUTH=1` на хостинге не ставить никогда: это обход подписи Telegram
  для локальной разработки.
- Полные тексты выступлений по ТЗ хранятся навсегда — базе нужен постоянный
  том/бэкапы, а не эфемерное хранилище.
